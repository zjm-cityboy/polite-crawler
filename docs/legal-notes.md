# 爬虫合法性调研笔记

> 本文档是项目「合规设计」的依据来源整理（2026-08 调研）。
> 结论先行：**爬虫技术本身不违法，风险来自"怎么爬"和"爬什么"**。

## 一、三条法律红线（绝对不碰）

依据《网络安全法》《数据安全法》《个人信息保护法》：

1. **公民个人信息、隐私数据**（身份证号、手机号、住址等）——
   杭州魔蝎数据案：非法爬取用户信息二次使用，构成侵犯公民个人信息罪
2. **企业商业秘密**
3. **受著作权保护的作品**（对外传播/商用场景）

## 二、刑事风险的核心：是否"突破/绕开"技术措施

《刑法》285 条相关判例的规律：**"突破"与"绕开"反爬措施是定罪的关键要件**——

| 判例 | 手段 | 结果 |
|---|---|---|
| 北京海淀"tt_spider"案（(2017)京0108刑初2384号，全国首例） | 破解视频网站防抓取措施 | 非法获取计算机信息系统数据罪，4 人获刑 |
| 上海王某案（2024） | 破解 API 加密算法、批量伪造设备指纹绕过防护售卖数据 | 追究刑责 |
| 超 8 亿条数据案 | 提供专门规避系统验证的有偿爬虫程序 | 非法获取计算机信息系统数据罪 |

本项目对应约束：**不模拟登录、不绕验证码、不破解任何接口防护**（合规中间件只做"少爬、慢爬"，不做"绕开"）。

## 三、民事风险的核心：反不正当竞争法

| 判例 | 要点 |
|---|---|
| 新浪微博诉脉脉案（(2016)京73民终588号，大数据不正当竞争第一案） | 第三方通过合作获得的数据，合作结束后继续抓取使用 = 不正当竞争 |
| 大众点评诉百度案（2017 终审） | 大规模呈现他人用户点评 = 不正当竞争（反法第二条一般条款） |
| 新浪微博诉字节跳动案（2021 一审） | 未经授权大规模移植微博内容构成不正当竞争 |

Robots 协议的地位：百度诉 360 案确立了它作为**行业惯例**的地位；
2025 年反不正当竞争法修订后，对违反 Robots 协议的自动化采集有了更明确的评价依据。
（注意：遵守 robots 不是免责金牌，违反 robots 则是明确的风险信号。）

本项目对应约束：`ROBOTSTXT_OBEY = True` 框架级强制 + 采集内容仅用于学习/自建知识库，不对外提供、不商用。

## 四、"公开数据"的边界认识

- "允许访问的公开数据 ≠ 允许爬虫抓取"（上海判例明确）
- 高频请求拖垮对方服务可能触及破坏计算机信息系统罪（286 条）——
  这就是**限速让步**（AutoThrottle + 每域名并发 1 + 随机间隔）不只是礼貌、更是法律边界管理的原因

## 五、本项目的合规清单（技术落地对照）

| 风险 | 技术落地 |
|---|---|
| robots 违反 | `ROBOTSTXT_OBEY = True` 强制 |
| 边界失控 | 站点白名单 + 聚焦采集（不做链接发现） |
| 服务器压力 | AutoThrottle 自动限速、并发 1、随机间隔 |
| 突破反爬 | 不登录、不绕验证码、UA 轮换仅降低指纹特征（行为仍礼貌） |
| SSRF（攻击面） | 中间件拦截私网/环回/保留地址 |
| 注入（攻击面） | SQL 全参数绑定 |
